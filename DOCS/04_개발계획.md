# 카페 운영 기록·수익성 확인 프로그램 개발 계획

- 문서 상태: 검토용 계획안
- 기준 문서: `Docs/01_PRD.md`, `Docs/02_FRD.md`, `Docs/03_TRD.md`
- 기준 시안: `Design/1~4/`, `Design/warm_artisanal_precision/DESIGN.md`
- 전체 실습 시간: 4시간(240분)
- EPIC 구현 및 사용자 확인 시간: 약 100분(추정)
- 범위 메모: PRD에는 수업 범위가 확인 대기, FRD 1.0에는 확정안으로 표시되어 있다. 이 계획은 사용자 요청에 따라 FRD 1.0의 FR-01~FR-07을 기준으로 작성했다. 아래 판매·비용 수정·삭제의 후속 이관은 권장 축소안이며 구현 전 범위 확인이 필요하다.

## 전체 작업 순서와 나눈 이유

기준자료·저장 준비 → 판매 입력 → 메뉴 수익성·비용 입력 → 재고·손익 확인 → 전체 흐름 재검증·배포 순서로 진행한다. 메뉴·재료 기준자료가 준비되어야 판매 원가를 계산할 수 있고, 판매·비용·재고가 저장된 뒤에 손익과 재료 잔량을 대조할 수 있다.

FR-01~FR-07 전체 기능을 100분 안에 구현하고 화면 확인까지 끝내기는 빠듯하다. 저장·계산·오류 검증은 줄이지 않고 시간에 맞추기 위한 권장 축소안은 **판매·비용 기록의 수정·삭제를 수업 후로 미루는 것**이다. 이 안의 영향은 수업 중 잘못 입력한 판매·비용을 프로그램에서 수정하거나 삭제할 수 없다는 점이다. 핵심 흐름과 입력 검증·계산 정확성·저장·기본 오류 처리는 유지한다.

| 제안 범위 | EPIC / Story | EPIC 구현·자동검사·화면 확인 예상 |
|---|---:|---:|
| 권장 축소안: 판매·비용 입력은 유지하고 수정·삭제는 수업 후로 미룸 | 3개 / 6개 | 약 100분 |
| FRD 수업 중 범위 전부 유지 | 3개 / 8개 예상 | 약 120분 이상 |

예상치는 추정이다. 전체 구현 범위를 유지할 경우 100분 안에 완료하기 어렵다는 위험이 있다.

## EPIC 1. 기준자료를 불러오고 판매를 저장한다 — 약 35분

**완료 기준:** 제공된 메뉴·재료 기준이 입력 선택지에 표시된다. 유효한 판매가 저장되고 새로고침 뒤에도 조회된다. 판매 입력 오류는 저장되지 않는다.

### Story 1 — 매장 기준자료를 확인한다 (약 10분)

- **사용자가 할 수 있는 일:** 메뉴와 재료의 기준 정보가 화면에 표시된 것을 확인한다.
- **자동 검사:** 초기 자료의 메뉴 8개, 재료 11개, 레시피 22개 등 기준 자료의 건수와 연결 ID를 대조한다. 빈칸과 0을 구별하고 초기 자료를 두 번 적재하지 않는지 확인한다.
- **화면에서 확인:** 메뉴 선택란에 실제 자료의 메뉴가 표시되고, 판매 화면에서 기준 단가를 확인한다. 기준 자료가 없거나 ID 연결이 깨진 항목은 임의로 다른 이름에 연결하지 않는다.
- **연속 동작 확인:** 화면을 새로고침해도 기준자료가 그대로 표시되는지 확인한다.

### Story 2 — 판매를 입력하고 저장한다 (약 25분)

- **사용자가 할 수 있는 일:** 판매일·메뉴·채널·수량·실제 단가·할인·수수료를 입력한다.
- **자동 검사:** 순매출은 FRD의 `수량 × 실제 단가 − 할인` 기준을 따른다. 수량 0, 음수·소수 수량, 음수 금액, 총액보다 큰 할인, 미래 판매일은 거부한다. 같은 날짜·메뉴·채널 입력은 하루 집계에 누적되는지 검사한다.
- **화면에서 확인:** 4,000원 메뉴 2개, 할인·수수료 0원이면 순매출 미리보기와 저장 결과가 8,000원이어야 한다. 2025년 7월 원두 20g을 사용하는 메뉴의 직접 원가는 460원으로 확인한다.
- **연속 동작 확인:** 저장 후 새로고침해도 기록이 남고, 같은 날·메뉴·채널에 3개를 추가 입력하면 집계 수량이 5개가 되는지 확인한다.

## EPIC 2. 메뉴 수익성과 운영 비용을 확인한다 — 약 25분

**완료 기준:** 메뉴별 직접비 기준 수익성이 FRD 계산 예시와 일치한다. 비용 입력이 저장되어 손익의 날짜별 비용으로 반영된다.

### Story 3 — 기간별 메뉴 수익성을 확인한다 (약 15분)

- **사용자가 할 수 있는 일:** 일 또는 월을 선택해 메뉴별 판매량·순매출·직접 원가·기여액·기여율을 확인한다.
- **자동 검사:** 메뉴 기여액은 순매출에서 직접 재료·적용 채널의 포장 원가만 뺀다. 공통 비용과 결제 수수료를 메뉴별로 나누지 않는다. 원가 기준이 없으면 0원 대신 계산 불가를 표시한다.
- **화면에서 확인:** 원두 20g 원가가 460원이고 순매출이 4,000원이면 기여액 3,540원, 기여율 88.5%가 표시된다.
- **연속 동작 확인:** 판매 저장 후 다시 조회해 메뉴 수익성에 저장된 판매가 반영됐는지 확인한다.

### Story 4 — 실제 운영 비용을 입력하고 저장한다 (약 10분)

- **사용자가 할 수 있는 일:** 날짜·비용 항목·금액과 선택 설명을 입력한다.
- **자동 검사:** 날짜·항목이 없거나 금액이 음수면 저장하지 않는다. 같은 날짜·분류·금액도 별도 지출일 수 있어 자동 병합하지 않는다. 비용 0원과 빈칸을 구분한다.
- **화면에서 확인:** 9월 18일에 비용 8,000원을 입력했을 때 비용 목록에 한 번 표시되는지 확인한다.
- **연속 동작 확인:** 새로고침 후 비용 기록이 유지되고, 이후 손익 조회에 한 번만 반영되는지 확인한다.

## EPIC 3. 재료 잔량과 실제 손익을 확인한다 — 약 40분

**완료 기준:** 입고·폐기·실사와 판매 사용량이 재고에 함께 반영되고, 일·월 손익이 중복 없이 계산된다. 판매 입력부터 이 결과까지 화면으로 따라갈 수 있다.

### Story 5 — 재료 변동을 기록하고 잔량을 확인한다 (약 20분)

- **사용자가 할 수 있는 일:** 재료의 입고·폐기 수량 또는 실사한 실제 수량을 입력한다.
- **자동 검사:** 재료·단위를 확인하고, 입고·폐기량은 양수, 실사량은 0 이상인지 검사한다. 폐기로 잔량이 음수가 되더라도 기록은 막지 않고 재고 부족 경고를 표시한다.
- **화면에서 확인:** FRD 예시대로 장부 1,000ml + 입고 500ml − 폐기 100ml − 판매 사용 400ml이면 잔량은 1,000ml다. 실사 920ml를 입력하면 80ml 조정 후 920ml가 표시되어야 한다.
- **연속 동작 확인:** 저장 후 새로고침해도 재고 변동 내역과 잔량이 유지되는지, 앞서 입력한 판매의 레시피 사용량이 재고에서 차감되는지 확인한다.

### Story 6 — 일·월 실제 손익을 확인한다 (약 20분)

- **사용자가 할 수 있는 일:** 하루 또는 월을 선택해 순매출·판매 원가·결제 수수료·날짜별 비용·실제 손익을 확인한다.
- **자동 검사:** `순매출 − 당시 판매 원가 − 결제 수수료 − 날짜별 비용` 계산을 검사한다. 재료 입고액과 월 비용 계획을 실제 손익에 중복해서 더하지 않는지, 자료가 없는 날을 매출 0원으로 채우지 않는지 확인한다.
- **화면에서 확인:** FRD 예시의 20,000 − 6,000 − 1,000 − 8,000은 5,000원이어야 한다. 기록 없는 기간은 “기록 없음”으로 표시한다.
- **연속 동작 확인:** 판매·비용·재고 기록을 저장한 뒤 새로고침하고, 해당 일·월 결과가 유지되며 앞선 EPIC의 판매 입력이 메뉴 수익성·손익·잔량에 이어지는지 확인한다.

## 전체 4시간 배분 초안

| 순서 | 작업 | 예상 |
|---|---|---:|
| 1 | 범위와 자료 위치 확인, GitHub·Vercel·Supabase 준비 | 15분 |
| 2 | 기존 시안을 FRD 범위에 맞춰 필요한 화면만 정리 | 25분 |
| 3 | 위 3개 EPIC 구현·자동검사·사용자 화면 확인 | 100분 |
| 4 | 판매 → 수익성 → 손익·잔량 전체 흐름 재검증 및 오류 수정 | 40분 |
| 5 | Vercel 미리보기 배포와 실제 화면 확인 | 40분 |
| 6 | 예비 시간 | 20분 |
| **합계** |  | **240분** |

이 배분은 계정·프로젝트 접근 권한이 미리 준비된다는 전제다. 시안의 마감 체크리스트나 안전재고 경고 등 FRD 제외 기능은 구현하지 않는다. 최초 자료 파일 경로는 PRD에 `C:\CAFE\E`로 되어 있지만 실제 제공 파일은 `C:\CAFE\Data`에 있으므로 작업 시작 전에 경로를 맞춰야 한다.

## 수업 후 확장 기능

FRD의 수업 후 범위는 엑셀 양식 내려받기·가져오기, 예상 손익, 주·분기·반기·연간 조회, 발주량 참고, JSON 백업·복원이다. 권장 축소안이 승인될 경우에만 판매·비용 기록의 수정·삭제도 후속 작업 후보로 옮긴다.

## 검토가 필요한 항목

- **권장 시간 축소안:** 판매·비용 기록의 수정·삭제를 수업 후로 미룬다. 승인 전에는 확정 범위로 보지 않는다.
- PRD와 FRD의 수업 범위 승인 상태가 다르다. 이 계획은 FRD 1.0을 작업 기준으로 삼았다.
- TRD에서 제안한 운영자 로그인·접근 통제는 FRD에 없으므로, 확정된 사용자 기능으로 계산하지 않았다. 운영 데이터를 배포하기 전 접근 통제 결정이 필요하다.
- 최초 자료 경로 표기(`C:\CAFE\E`)와 실제 폴더(`C:\CAFE\Data`)가 다르다.
