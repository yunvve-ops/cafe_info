## 전체 사용 순서

1. 프로그램에서 프렙 카페의 메뉴·재료·레시피 기준 정보를 확인한다. 기준 목록은 첨부 엑셀·JSON의 8개 메뉴, 11개 재료, 22개 레시피다.
2. 판매 일자·메뉴·채널·수량·실제 판매가·할인·결제 수수료를 입력한다. 프로그램이 순매출과 재료·포장 원가를 산출해 저장한다.
3. 판매 기록을 조회하고 집계 값을 수정하거나 해당 일자·메뉴·채널 기록을 삭제한다.
4. 기준 기간을 골라 메뉴별 수익성을 비교한다.
5. 실제 비용의 날짜·항목·금액을 기록하고 수정·삭제한다.
6. 재료 입고·폐기·실사 수량을 기록하고, 판매 레시피 사용량을 반영한 재고 잔량을 확인한다.
7. 일·월 실제 손익을 확인한다. 수업 후에는 주·분기·반기·연간 조회와 예상 손익을 확인한다.
8. 수업 후 엑셀 양식을 내려받아 판매·비용 기록을 가져오고, 전체 데이터를 백업하거나 백업본으로 복원한다.
9. 수업 후 필요 발주량 참고를 확인한다. 프로그램은 주문을 자동 전송하지 않는다.

## 공통 자료 기준

- 첨부 엑셀과 JSON은 같은 가상 매장 데이터다. 초기 과거 자료를 넣을 때는 둘 중 하나만 사용하고, 둘을 차례로 가져와 중복 적재하지 않는다.
- 실제 자료의 기간은 2025-07-01~2026-09-18이다. 영업달력은 2026-09-30까지 있지만 그 이후 판매·비용 기록은 없다. 미마감일을 판매 0건으로 채우지 않는다.
- 금액은 원화·부가세 제외다. 재료 단위는 g·ml·개다. 구매 가격은 구매 포장 전체 가격이고 레시피 사용량은 메뉴 1개 기준이다.
- 판매 기록은 주문 단위가 아닌 날짜·메뉴·채널별 집계로 관리한다. 자료의 행 수, ID와 빈칸/0 의미를 보존한다.
- 월 비용 계획과 날짜별 비용은 같은 비용의 다른 단위 기록이므로 실제 손익에서 더하지 않는다. 실제 손익은 날짜별 비용 기록을 사용한다.
- 재료 가격이나 레시피가 바뀌어도 과거 판매의 당시 순매출·원가 스냅샷은 바꾸지 않는다. 신규 판매는 해당 판매일에 적용되는 레시피와 재료 가격을 사용한다.
- 자료에 없는 메뉴, 재료, 판매가, 분류를 시안에서 가져오지 않는다. 메뉴·재료 ID를 기준으로 연결하고 이름은 첨부 기준 자료를 표시한다.
- 기록이 없거나 값이 비어 있는 것을 숫자 0으로 보정하지 않는다. 금액이 명시적으로 0인 경우는 0으로 보존한다.

## 기능별 요구사항

### FR-01 판매 기록 입력·조회·수정·삭제 — 수업 중

**사용자가 하는 일과 입력**

- `판매 기록 등록`을 선택해 판매일, 메뉴, 판매 채널, 수량, 실제 판매 단가, 할인액, 결제 수수료를 입력한다. 기본 단가는 메뉴 기준가로 채워지며 행사·실판매가는 수정할 수 있다.
- 재료·포장 원가는 사용자가 입력하지 않는다. 연결된 레시피와 가격 이력에서 계산한다.
- 저장한 판매 기록을 날짜·메뉴·채널별로 조회한다. 해당 집계 행을 선택해 수정하거나 삭제한다.

**프로그램이 하는 일**

- 판매일·메뉴·채널·수량·판매가·할인·수수료를 검증한다. 수량은 양의 정수, 판매가·할인·수수료는 0 이상이다.
- 해당 판매일 메뉴가와 사용자가 입력한 실제 단가·할인을 이용한다. `순매출 = 수량 × 실제 단가 − 할인액`으로 계산한다. 할인액은 총 판매액을 넘을 수 없다.
- 메뉴 1개당 재료 원가는 적용 가격의 구매 용량으로 단위 가격을 구해 레시피 양에 적용한다. 포장 재료는 레시피가 포장 채널에만 지정한 경우 해당 채널에만 적용한다. 합계는 중간 단계에서 반복 반올림하지 않고 최종 원화 표시에서 가장 가까운 원으로 반올림한다.
- 동일 일자·메뉴·채널의 수동 입력은 하루 집계에 누적한다. 기존 합계와 새 입력량·금액을 더한 미리보기를 저장 전에 보여준다. 사용자가 목록에서 수정하면 집계 전체의 최종값을 바꾸고, 삭제하면 해당 집계 전체를 제거한다.
- 판매량이 바뀌면 메뉴 수익성, 실제 손익, 레시피 사용량 기반 재고가 함께 다시 계산된다.

**화면과 파일에 나오는 결과**

- 판매 입력 화면에는 날짜·메뉴·채널·수량·단가·할인·결제 수수료와 저장 예상 순매출·원가가 표시된다.
- 판매 목록에는 날짜, 메뉴, 채널, 수량, 단가, 할인, 순매출, 원가와 수정·삭제 조작이 표시된다.
- 기록이 성공적으로 저장되면 일·월 집계와 연결된 메뉴·재고 결과가 갱신된다.
- 이 기능에서 판매 내역 CSV/엑셀 내보내기는 제공하지 않는다. 엑셀 입력 양식 파일은 FR-08에서 제공한다.

**오류나 예외가 있을 때의 동작**

- 필수값 누락, 존재하지 않는 메뉴/채널, 0·음수·소수 수량, 음수 금액, 할인액이 총 판매액보다 큰 경우 저장하지 않고 수정할 항목을 알린다.
- 적용할 레시피·재료가격이 없거나 단위가 맞지 않으면 원가를 0원으로 가정하지 않고 “원가 확인 필요”로 표시한다. 이 판매를 포함한 손익도 미완성 상태로 표시한다.
- 저장 실패 시 성공 알림·집계 갱신을 하지 않는다. 입력값은 남겨 수정 또는 재시도할 수 있게 한다.
- 삭제 전 확인을 받는다. 삭제를 취소하면 기록과 연결된 집계가 바뀌지 않는다.
- 미래 날짜의 실제 판매는 입력할 수 없다. 미래 예상값은 FR-09에서 다룬다.

**직접 확인할 방법**

- 기준 판매가 4,000원인 메뉴를 2개, 할인 0원, 수수료 0원으로 입력하면 순매출 미리보기가 8,000원이어야 한다.
- 같은 날짜·메뉴·채널에 3개를 더 입력하면 해당 하루 집계가 5개가 되는지 확인한다.
- 수량 0, 없는 메뉴 ID, 총액보다 큰 할인액을 저장할 때 거절되는지 확인한다.
- 판매 집계를 수정·삭제한 뒤 손익 및 재고 사용량이 수정된 값에 맞춰 변하는지 확인한다.

### FR-02 메뉴별 수익성 — 수업 중

**사용자가 하는 일과 입력**

- 일·월 기준 기간을 선택해 메뉴별 비교를 확인한다. 수업 후에는 다른 기간 조회도 가능하다.
- 메뉴를 고르면 메뉴의 직접 원가 구성을 확인한다.

**프로그램이 하는 일**

- 메뉴별 기여액을 **순매출에서 직접 재료비와 적용 채널의 포장비를 뺀 값**으로 계산한다. 임대료·인건비 등 공통비용과 결제 수수료는 메뉴별 기여액에 나누지 않는다. 결제 수수료는 FR-05의 기간 손익에 포함한다.
- 기여율은 메뉴 기여액을 순매출과 비교한 비율로 표시한다. 순매출이 0이면 비율은 계산 불가로 표시한다.
- 과거 행은 당시 저장된 재료·포장 원가를 사용한다. 신규 판매는 판매일에 적용되는 재료 구매가격 이력과 해당 레시피 버전을 사용한다.
- 메뉴별 목록은 기여액·기여율을 비교할 수 있게 정렬할 수 있고, 상세에는 재료명·1개당 사용량·단위 가격·원가가 표시된다. 레시피 수정·원가 시뮬레이션은 제공하지 않는다.
- **계산 예시:** 2025년 7월 원두 구매가는 1,000g당 23,000원, 아메리카노 레시피 사용량은 20g이므로 원두 원가는 460원이다. 순매출 4,000원, 포장비 없음이면 메뉴 기여액은 3,540원이고 기여율은 88.5%다. 이 값은 공통비용과 결제 수수료를 배분하기 전이다.

**화면과 파일에 나오는 결과**

- 기간, 메뉴명, 순매출, 직접 재료·포장 원가, 기여액, 기여율과 기간 판매량을 보여준다.
- 선택 메뉴의 레시피별 원가 분해를 화면에서 확인한다. 별도 결과 파일은 생성하지 않는다.

**오류나 예외가 있을 때의 동작**

- 판매가 없는 메뉴는 “판매 기록 없음”으로 표시하고 임의의 0% 순위를 부여하지 않는다.
- 가격·레시피가 비었거나 기준 단위가 맞지 않으면 원가·기여액을 0으로 대신하지 않고 해당 메뉴를 “계산 불가”로 표시한다.
- 메뉴 이름과 ID가 맞지 않는 자료는 이름만으로 임의 연결하지 않는다.

**직접 확인할 방법**

- 위 아메리카노 예시에서 20g 원가 460원, 기여액 3,540원, 기여율 88.5%를 확인한다.
- 포장 채널 메뉴에 포장 재료가 더해지고 매장 이용에는 그 포장비가 들어가지 않는지 확인한다.
- 레시피를 제거한 메뉴는 원가 0원이 아니라 계산 불가로 표시되는지 확인한다.

### FR-03 비용 기록 입력·조회·수정·삭제 — 수업 중

**사용자가 하는 일과 입력**

- 비용 날짜, 비용 항목 분류, 금액을 입력한다. 인식 내용/설명은 선택 입력이다.
- 기록을 조회하고 개별 비용을 수정하거나 삭제한다.
- 날짜는 사용자가 고칠 수 있으며, 현재 선택된 날짜를 기본값으로 제공한다.

**프로그램이 하는 일**

- 각 실제 지출을 별도 기록으로 저장한다. 같은 날 같은 분류의 지출도 임의로 합치거나 덮어쓰지 않는다.
- 비용 기록을 실제 손익의 해당 기간에 한 번 반영한다.
- 월 비용 계획은 계획 자료로 보존하며 실제 비용 기록과 더하지 않는다.

**화면과 파일에 나오는 결과**

- 목록에 날짜·분류·설명·금액이 표시된다. 수정·삭제 후 일·월 손익이 다시 계산된다.
- 비용 목록을 별도 파일로 내보내지 않는다. 수업 후 입력 양식은 FR-08에서 제공한다.

**오류나 예외가 있을 때의 동작**

- 날짜·항목·금액 누락, 없는 분류, 음수 금액은 저장하지 않고 해당 항목을 알린다. 비용 금액 0원은 명시적으로 입력한 경우만 기록한다.
- 동일 날짜·분류·금액이어도 서로 다른 지출일 수 있으므로 자동 합산·삭제하지 않는다.
- 삭제 취소 시 기존 지출과 손익을 유지한다. 저장 실패 시 목록과 손익을 갱신하지 않고 입력값을 보존한다.

**직접 확인할 방법**

- 9월 18일에 비용 8,000원을 입력하면 일 비용과 9월 실제 손익에 한 번 반영되는지 확인한다.
- 같은 날·분류에 다른 비용을 추가해도 기존 항목이 보존되는지 확인한다.
- 비용 수정·삭제 후 합계가 바뀌고 삭제 취소 후에는 유지되는지 확인한다.

### FR-04 재료 입고·폐기·실사 및 잔량 — 수업 중

**사용자가 하는 일과 입력**

- 재료, 날짜, 변동 유형, 수량을 입력한다. 유형은 입고·폐기·실사다.
- 입고·폐기 수량은 양수로 입력한다. 실사에는 실제로 센 현재 수량을 입력한다.
- 공급사·구매단가·사유를 제공할 수 있다. 자료에서 비어 있을 수 있는 항목이므로 이 세 항목은 필수가 아니다.

**프로그램이 하는 일**

- 입고는 재고에 더하고, 폐기는 재고에서 뺀다. 재료 단위는 해당 재료의 기준 단위(g·ml·개)를 쓴다.
- 판매 행에 연결된 레시피 사용량을 재고 잔량에서 차감한다. 포장 전용 재료는 포장 채널 판매에만 차감한다. 판매 수량 수정·삭제는 해당 차감량을 함께 바로잡는다.
- 실사량을 입력하면 프로그램은 장부 잔량과 실측량의 차이를 계산하고 조정 기록을 남겨 잔량을 실측량에 맞춘다.
- **잔량 계산 예시:** 우유 장부량 1,000ml에 입고 500ml, 폐기 100ml를 기록하고, 라떼 2잔에 200ml씩 사용하면 장부 잔량은 1,000ml다. 실제 수량을 920ml로 세었다면 80ml를 실사 차이로 조정해 잔량을 920ml로 맞춘다.
- 수업 중에는 재료 잔량만 제공한다. 안전재고 경보 및 발주량은 FR-10 범위다.

**화면과 파일에 나오는 결과**

- 재료별 기준 단위, 현재 장부 잔량과 날짜별 입고·폐기·실사 내역을 표시한다.
- 판매 사용량 계산에 필요한 레시피가 없으면 재료 잔량에 계산되지 않은 사용량이 있음을 알린다.
- 재고 변동 전용 파일은 생성하지 않는다.

**오류나 예외가 있을 때의 동작**

- 없는 재료, 변동 유형 누락, 단위 불일치, 입고·폐기의 0·음수 수량, 음수 실사량은 저장하지 않는다.
- 폐기량이 현재 잔량보다 커 잔량이 음수가 되는 경우 기록을 막지 않고 “재고 부족 또는 누락 기록 확인” 경고를 표시한다. 실제 폐기였을 가능성을 기록으로 보존한다.
- 빈 단가·공급사는 0원으로 변환하지 않는다. 수량 기록은 저장하되 원가 산출에 필요한 값이 없으면 비용 결과를 확인 필요로 표시한다.
- 재고 이벤트 자체의 수정·삭제는 PRD가 요구하지 않아 제공하지 않는다. 새 실사 조정 기록으로 실제 차이를 바로잡는다.

**직접 확인할 방법**

- 위 우유 예시에서 입고·폐기·판매 사용 후 잔량이 1,000ml인지 확인한다.
- 920ml 실사값을 입력하면 80ml 차이 조정과 최종 잔량 920ml를 확인한다.
- 재료 g 칸에 ml를 입력하거나 수량 -10을 입력하면 저장이 거절되는지 확인한다.

### FR-05 일·월 실제 손익 — 수업 중

**사용자가 하는 일과 입력**

- 하루 또는 월을 선택해 실제 손익을 조회한다.
- 판매·비용·재고 기록을 수정한 뒤 같은 기간을 다시 확인한다.

**프로그램이 하는 일**

- **실제 운영 손익 계산:** 순매출 − 당시 판매 재료·포장 원가 − 실제 결제 수수료 − 날짜별 운영비용.
- 재료 구매 입고액은 입고일의 손익 비용으로 다시 더하지 않는다. 입고 재료가 메뉴 판매에 사용될 때 판매 원가로 반영해 구매액과 사용 원가의 중복을 막는다.
- 월 비용 계획은 실제 손익에 넣지 않는다. 비용 기록과 월 계획을 함께 보여줄 경우 계획/실적을 구분한다.
- **계산 예시:** 순매출 20,000원, 재료·포장 원가 6,000원, 결제 수수료 1,000원, 날짜별 운영비용 8,000원이면 실제 운영 손익은 5,000원이다.
- 값은 부가세 제외 운영 참고치이며 세무 신고나 회계 장부를 대체하지 않는다.

**화면과 파일에 나오는 결과**

- 선택한 일·월의 순매출, 재료·포장 원가, 결제 수수료, 운영비용, 실제 운영 손익을 구분해 표시한다.
- 계획 비용을 표시하면 실제 비용과 별도 열/구역으로 표시한다. 보고서 파일은 생성하지 않는다.

**오류나 예외가 있을 때의 동작**

- 기록이 없는 기간은 “기록 없음”으로 표시한다. 0원은 사용자가 명시적으로 입력했거나 계산 결과가 실제 0인 경우만 표시한다.
- 원가·수수료 등 손익 필수 정보가 비어 있으면 완성 손익인 것처럼 계산하지 않고 확인 필요로 표시한다.
- 2026-09-18 이후의 미마감 달력 날짜는 판매 0원으로 보충하지 않는다. 실제 자료가 있는 기간은 자료 종료일을 함께 알려 부분 기간임을 표시한다.
- 날짜별 비용과 월 비용 계획을 합산하지 않는다.

**직접 확인할 방법**

- 20,000 − 6,000 − 1,000 − 8,000 예시가 5,000원으로 표시되는지 확인한다.
- 월 비용 계획과 날짜별 비용이 함께 있을 때 계획이 실제 지출 합계에 중복되지 않는지 확인한다.
- 자료 종료일 이후 달력 날짜에 매출 0원이 자동 생성되지 않는지 확인한다.

### FR-06 기간 조회 — 일·월 수업 중, 주·분기·반기·연간 수업 후

**사용자가 하는 일과 입력**

- 조회 단위와 날짜/연도를 선택한다. 수업 중 제공되는 단위는 일·월이고, 수업 후 주·분기·반기·연간 단위가 추가된다.

**프로그램이 하는 일**

- 판매·비용·재고를 선택 기간에 한 번씩 포함하고 해당 기간의 메뉴 수익성, 실제 손익, 재고 결과를 다시 계산한다.
- 주는 월요일~일요일, 분기는 1~3월·4~6월·7~9월·10~12월, 반기는 1~6월/7~12월, 연간은 1~12월로 집계한다.
- 예: 2026년 9월에는 9월 1~18일 실제 자료까지만 집계하며, 9월 19~30일 달력은 매출 0원으로 포함하지 않는다.

**화면과 파일에 나오는 결과**

- 선택한 기간의 시작일·종료일과 집계값을 표시한다. 실제 자료가 기간 전체를 채우지 못하면 자료 종료일/부분 기간 상태를 표시한다.
- 기간별 보고서는 화면 조회만 지원한다. 결과 파일 내보내기는 제공하지 않는다.

**오류나 예외가 있을 때의 동작**

- 시작일이 종료일보다 늦거나 유효하지 않은 날짜면 조회하지 않고 수정이 필요한 날짜를 알린다.
- 해당 기간 기록이 없으면 “기록 없음”으로 표시한다.
- 기간 밖 행을 포함하거나 하나의 행을 두 기간에 중복 포함하지 않는다.

**직접 확인할 방법**

- 2026-09-18 일 조회 값이 2026-09 월 합계의 일부인지 확인한다.
- 2026-09 월 집계가 실제 자료가 있는 18일까지의 결과임을 확인한다.
- 추후 주·분기·반기·연간 조회에서 경계 날짜의 기록이 정해진 한 기간에만 포함되는지 확인한다.

### FR-07 기록 저장·기본 오류 처리 — 수업 중

**사용자가 하는 일과 입력**

- 판매·비용·재고 기록을 작성하고 저장한다. 저장 후 해당 기록과 보고서를 다시 조회한다.

**프로그램이 하는 일**

- 성공한 입력·수정·삭제를 저장하고 연결된 화면 결과를 갱신한다.
- 사용자가 화면을 나갔다 돌아와도 성공 저장한 기록을 유지한다.
- 데이터 유효성을 먼저 확인한 뒤 성공 결과를 보여준다.

**화면과 파일에 나오는 결과**

- 성공 시 저장한 항목과 갱신 결과가 표시된다. 저장 자체는 별도 파일로 내려받지 않는다.
- 유효하지 않은 값이나 저장 실패는 알아볼 수 있는 안내로 표시한다.

**오류나 예외가 있을 때의 동작**

- 실패한 값이 성공으로 보이거나 집계에 먼저 포함되지 않는다. 저장 실패 시 입력값을 유지한다.
- 빈칸과 0, 사용할 수 없는 ID와 이름을 구분한다.
- 재시도 때문에 같은 수동 기록이 두 번 저장되지 않도록 중복 결과를 확인한다.

**직접 확인할 방법**

- 정상 기록을 저장한 후 다른 화면을 거쳐 다시 조회해 기록이 유지되는지 확인한다.
- 필수값을 비운 저장은 거부되고 입력값을 유지하는지 확인한다.
- 저장 실패 후 재시도해도 동일 기록이 한 번만 반영되는지 확인한다.

### FR-08 엑셀 양식 내려받기·가져오기 — 수업 후

**사용자가 하는 일과 입력**

- 판매·비용 입력용 `.xlsx` 양식을 내려받아 자료를 채운다.
- 작성 파일을 선택해 가져오기를 요청한다.

**프로그램이 하는 일**

- 양식에는 판매 시트와 비용 시트를 제공한다. 판매 열은 판매일, 메뉴 ID, 채널, 수량, 실제 단가, 할인액, 결제 수수료다. 비용 열은 날짜, 항목 분류, 금액, 설명이다. 데이터 금액은 원화·부가세 제외다.
- 가져오기 전에 파일의 시트·열과 각 행의 날짜, 메뉴 ID/채널, 수량·금액을 검사한다.
- 파일 전체가 유효할 때만 반영한다. 한 행이라도 오류가 있으면 아무 행도 저장하지 않고 시트·행·항목별 오류를 표시한다.
- 판매는 날짜·메뉴·채널별 집계 행이다. 같은 파일 안의 동일 조합 중복은 가져오기를 거부한다. 기존 행과 조합이 같으면 해당 일자 집계 교체 여부를 표시하고 확인을 받은 뒤 교체한다. 값이 동일한 재가져오기는 중복으로 건너뛴다.
- 비용 행은 실제로 같은 날짜·분류·금액의 별도 지출일 수 있으므로 행 내용만으로 합치지 않는다. 이미 가져온 파일을 다시 가져오면 중복 파일 경고를 표시하고 재반영하지 않는다.
- 초기 샘플 데이터는 판매·비용 양식과 별개다. 엑셀/JSON 샘플 전체를 둘 다 적재하지 않도록 안내한다.

**화면과 파일에 나오는 결과**

- 내려받은 빈 양식에는 입력 열과 작성 안내가 있다. 샘플 판매나 비용 자료를 실데이터로 오인하게 넣지 않는다.
- 가져오기 완료 시 추가·교체·건너뛴 행 수를 표시한다. 실패 시 저장되지 않은 오류 행 목록을 표시한다.
- 오류 목록은 파일, 시트, 행, 열/항목과 고칠 내용을 식별할 수 있게 한다.

**오류나 예외가 있을 때의 동작**

- 손상 파일, 필요한 시트/열 누락, 잘못된 날짜/ID/채널/단위, 비정수 또는 음수 판매 수량, 음수 금액, 할인 초과, 중복 행이 있으면 파일 전체를 반영하지 않는다.
- 빈칸을 0으로 바꾸거나 모르는 메뉴를 비슷한 이름으로 자동 연결하지 않는다.
- 사용자가 취소하거나 검증 실패 시 기존 기록은 그대로 둔다.

**직접 확인할 방법**

- 양식에 유효한 판매 1행과 비용 1행을 넣어 두 행의 날짜·메뉴·금액이 일치하는지 확인한다.
- 없는 메뉴 ID를 추가한 파일은 전체 반영이 보류되고, 해당 행을 가리키는 오류가 나오는지 확인한다.
- 같은 파일을 다시 선택하면 비용이 두 번 더해지지 않는지 확인한다.
- 동일 판매 조합의 값이 다른 파일을 가져오면 집계 교체 확인을 거치는지 확인한다.

### FR-09 예상 손익 — 수업 후

**사용자가 하는 일과 입력**

- 예상 기간을 고르고 예상 순매출, 판매 원가, 결제 수수료, 비용을 입력한다. 항목별 예상 비용은 분류별로 입력한다.

**프로그램이 하는 일**

- 자동 예측 모델 대신 사용자가 입력한 예상값을 이용한다. 그래야 운영자가 전망의 근거를 파악하고 바로 조정할 수 있다.
- **예상 손익 계산:** 예상 순매출 − 예상 판매 원가 − 예상 결제 수수료 − 예상 운영비용.
- 예시: 예상 순매출 10,000원, 예상 원가 3,000원, 예상 수수료 0원, 예상 운영비 5,000원이면 예상 운영 손익은 2,000원이다.
- 실제 기록을 수정하거나 예상 숫자를 실제 실적으로 저장하지 않는다.

**화면과 파일에 나오는 결과**

- 예상 기간·입력한 가정값·예상 손익을 실제 실적과 분리해 표시한다.
- 예상 보고서 파일은 생성하지 않는다.

**오류나 예외가 있을 때의 동작**

- 필수 예상값이 빠지거나 음수 금액이면 계산 완료로 표시하지 않고 해당 값을 요구한다. 사용자가 명시적으로 0을 입력한 항목은 0으로 계산한다.
- 예상값이 부족하면 손익 0원으로 대신하지 않는다.
- 예상 입력/계산 오류는 과거 실제 기록을 바꾸지 않는다.

**직접 확인할 방법**

- 10,000 − 3,000 − 0 − 5,000 예시가 2,000원인지 확인한다.
- 예상 원가를 4,000원으로 바꾸면 예상 손익만 1,000원으로 바뀌고 실제 손익은 유지되는지 확인한다.
- 필수 예상값을 비우면 결과가 미완성으로 표시되는지 확인한다.

### FR-10 필요 발주량 참고 — 수업 후

**사용자가 하는 일과 입력**

- 재료별 현재 잔량과 제안 발주량을 조회한다. 사용자는 필요한 경우 추천값을 참고해 실제 주문을 별도로 결정한다.

**프로그램이 하는 일**

- 최근 완료된 20영업일의 레시피 기준 일평균 사용량을 구한다. 영업 여부와 마감 여부가 확인되지 않은 날짜는 평균에서 제외한다.
- 납기일수와 안전재고일수는 영업일 기준으로 사용한다.
- **제안 계산:** 목표량은 일평균 사용량 × (납기일수 + 안전재고일수)이고, 부족량은 목표량 − 현재 잔량이다. 부족량이 양수면 구매 포장량 단위로 올림한다. 부족량이 0 이하이면 발주 제안은 0포장이다.
- 예시: 하루 100g 사용, 납기 2영업일, 안전재고 2영업일이면 목표량 400g이다. 현재 250g이면 150g 부족하다. 구매 포장량이 1,000g이면 1포장을 제안한다.
- 제안량은 참고값이며 주문서를 공급사로 보내지 않는다.

**화면과 파일에 나오는 결과**

- 재료별 현재 잔량, 기준 단위, 최근 일평균 사용량, 납기·안전재고 기준, 부족량과 구매 포장 기준 제안 포장 수를 표시한다.
- 공급사 발주서나 주문 파일은 만들지 않는다.

**오류나 예외가 있을 때의 동작**

- 최근 완료 영업일 기록이 없으면 계산하지 않고 “사용량 자료 부족”이라고 알린다.
- 현재 잔량, 납기일수, 안전재고일수, 구매 포장량이 없거나 단위 환산이 안 되면 0포장으로 표시하지 않고 “기준 정보 확인 필요”라고 표시한다.
- 음수 제안 수량은 표시하지 않는다. 재고가 목표량을 넘으면 발주 불필요/0포장으로 표시한다.

**직접 확인할 방법**

- 하루 100g, 납기 2일, 안전재고 2일, 현재 250g, 포장량 1,000g 예시에서 목표 400g·부족 150g·제안 1포장을 확인한다.
- 납기나 포장량을 비우면 0포장이 아니라 계산 불가 안내가 나오는지 확인한다.

### FR-11 데이터 백업·복원 — 수업 후

**사용자가 하는 일과 입력**

- 전체 데이터를 백업 파일로 내려받는다.
- 복원할 JSON 백업 파일을 선택하고, 복원 요약을 확인한 뒤 적용을 승인한다.

**프로그램이 하는 일**

- 백업에는 메뉴·재료·레시피·가격 이력 등 기준정보와 판매·비용·재고 기록, 조회/전망 관련 입력을 포함한다.
- 백업 파일은 JSON 형식으로 제공한다. 이는 모든 종류의 연결 관계와 빈칸/0 구분을 보존하기 위한 데이터 백업이며, 엑셀 입력 양식과 구분한다.
- 복원은 현재 매장 데이터를 백업본 전체로 교체한다. 적용 전 파일의 자료 ID/형식·필수 정보·포함 건수를 확인해 미리 보여주고, 기존 자료를 교체한다는 최종 확인을 받는다.
- 교체 직전에 현재 자료의 안전 백업을 만든다. 복원 후에는 기록 종류별 적용 건수와 복원 시점을 표시한다.

**화면과 파일에 나오는 결과**

- 백업 성공 시 내려받을 JSON 파일과 생성 시점, 자료 범위를 알려준다.
- 복원 전에는 대체될 기존 기록 수와 백업본 기록 수를 비교해 표시한다. 복원 후에는 완료 상태와 적용 건수를 보여준다.

**오류나 예외가 있을 때의 동작**

- 손상 파일, 지원하지 않는 자료 버전/ID, 필수 기준정보 누락, 연결되지 않는 레코드가 있으면 복원하지 않고 문제를 표시한다.
- 사용자가 최종 교체를 취소하거나 파일 검증이 실패하면 기존 데이터는 그대로 유지된다.
- 같은 백업본 복원은 병합하지 않고 전체 교체이므로 동일 기록이 누적되지 않는다. 복원 전에 만든 안전 백업으로 직전 상태를 되돌릴 수 있다.

**직접 확인할 방법**

- 백업 후 판매·비용·재고·기준정보 건수가 파일 요약과 맞는지 확인한다.
- 동일 백업을 두 번 복원해도 기록 수가 두 배가 되지 않는지 확인한다.
- 손상된 파일을 선택하거나 최종 교체를 취소한 경우 기존 기록이 유지되는지 확인한다.

## 시안 반영 및 제외 원칙

- 시안 1~4의 메뉴·재료·가격과 수치가 실제 자료와 다르므로, 화면의 실제 정보는 첨부 엑셀/JSON의 ID와 기준 자료를 사용한다. 시안 숫자는 기능 요구사항·검증 기준으로 쓰지 않는다.
- 시안에서 PRD에 맞는 판매 입력, 판매 관리, 메뉴별 수익성, 비용 등록, 재료 변동과 잔량 조회 기능을 반영한다.
- 시안의 검색/필터, 판매 CSV 내보내기, 영업 마감 확정 및 체크리스트, 월 목표, 원가 시뮬레이션, 레시피 편집, 안전재고 임계 경보, 자동 발주 생성, PDF 매뉴얼은 PRD에 요구되지 않아 이번 제품 기능에 포함하지 않는다.
- 시안 2의 시간별 개별 전표 표시는 원자료의 집계 구조와 맞지 않으므로 채택하지 않는다. 화면은 날짜·메뉴·채널 집계 행을 보여준다.
- 시안에서 날짜 입력이 없는 비용·재고 조작은 날짜를 요구한다. 기본값은 현재 선택 날짜지만 사용자가 변경할 수 있다.

## 용어

- **FRD**: 기능 요구사항 문서. 사용자의 입력부터 프로그램 처리와 결과까지 정리한 문서다.
- **기여액(공헌이익)**: 순매출에서 메뉴의 직접 재료·포장 원가를 뺀 금액. 이 문서에서는 공통 비용과 결제 수수료를 빼기 전이다.
- **실사**: 재료를 직접 세어 실제 보유량을 확인하는 일.
- **장부 잔량**: 기초재고·입고·폐기·판매 사용량·실사 차이를 기록에 반영한 재고량.
- **스냅샷**: 판매 당시 값으로 저장되어 과거 계산에 보존되는 단가·원가 등.
- **레시피**: 메뉴 1개에 필요한 재료와 수량 목록.
- **영업일**: 매장이 영업한 날. 납기·안전재고 일수와 발주 계산에서 사용하는 기준이다.
- **예상값**: 사용자가 미래 기간의 결과를 가정해 입력한 값. 과거 실제 기록과 구분한다.

**범위 요약:** 수업 중에는 판매 입력부터 메뉴 수익성, 실제 손익, 재료 잔량까지 연결한다. 수업 후에는 엑셀 가져오기, 예상 손익, 확대 기간 조회, 발주량 참고, 백업·복원을 제공한다. POS 자동 연동·자동 발주·세무 신고·회계 장부 작성은 포함하지 않는다.
